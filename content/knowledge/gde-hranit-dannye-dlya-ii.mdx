# Три вопроса перед выбором хранилища

Где физически находятся данные, кто имеет к ним доступ и что остаётся в логах. Ответы на эти вопросы важнее, чем название облачного провайдера.

# Разделяйте данные по sensitivity

- Публичные материалы и документация.
- Внутренние регламенты и базы знаний.
- Персональные данные и коммерческая тайна.

Для каждой категории должен быть свой уровень доступа и свои правила передачи во внешние модели.

# Контур обработки

Определите, какие данные можно отправлять в облачную модель, а какие должны оставаться внутри инфраструктуры. Для чувствительных сценариев используйте маскирование или локальные модели.

# Доступы

Не выдавайте приложениям права администратора. Отдельный сервисный аккаунт, минимальные права, ротация ключей — базовая гигиена, которая предотвращает большинство инцидентов.

# Логи

Храните запросы, ответы, источники и действия пользователя. Это нужно не только для безопасности, но и для отладки качества: без логов невозможно понять, почему ассистент ошибся.

# Сроки хранения

У каждого типа данных должен быть срок. «Храним всё бессрочно» — это не стратегия, а накопление риска. Настройте автоматическую очистку.

# Минимальная схема

1. Отдельное хранилище для чувствительных данных.
2. Сервисные аккаунты с минимальными правами.
3. Маскирование персональных данных до отправки в модель.
4. Логи с ограниченным доступом и сроком хранения.
5. Регламент на удаление данных по запросу.
